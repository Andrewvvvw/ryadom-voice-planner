# HTTP API

Сервер отдаёт UI и JSON API с одного origin. Ошибка: `{ "error": "понятное сообщение" }`. Ответы API имеют `Cache-Control: no-store`. Все операции ограничены cookie текущего браузера. В curl надо сохранять cookie.

```bash
curl -c /tmp/ryadom.cookies -X POST http://localhost:3000/api/bootstrap
curl -b /tmp/ryadom.cookies http://localhost:3000/api/stats
```

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | Проверка доступности процесса, не готовности БД |
| POST | `/api/bootstrap` | Создать пространство и идемпотентно импортировать CSV |
| GET | `/api/stats` | Всего, импортировано, выполнено, сегодня, встречи на 7 дней |
| GET | `/api/events` | Список и точное количество по фильтрам |
| GET | `/api/search?q=...` | До 50 совпадений по всей истории, локальный поиск |
| POST | `/api/chat` | Интерпретация запроса и выполнение действия |
| GET | `/api/history?conversationId=UUID` | Последние 50 обменов диалога |
| GET | `/api/export` | Все события пространства в JSON |

## Диалог

```json
{
  "text": "Поставь встречу с Иваном завтра",
  "conversationId": "63f8ef67-4cd1-466e-90af-9e3b8ec17f48",
  "requestId": "d85063e6-21c9-4b57-8cef-c44c43776c87",
  "timezone": "Europe/Minsk"
}
```

Для следующего сообщения оставить `conversationId`, сгенерировать новый `requestId`. При повторе после сетевой ошибки использовать **тот же** `requestId` и тело: сервер вернёт сохранённый ответ. Изменённое тело с уже использованным ID даёт 409. Новый ID диалога начинает новую историю и сохраняет события.

`targetId` — необязательный ID выбранного события, используется кнопками карточки для выполнения, удаления и переноса. Несуществующая или чужая запись даёт 404. Удаление всегда требует второго сообщения «Да».

Ответ содержит `text`, `events`, `action`, `engine: local|llm`, `degraded` и `pending`. Для списка также возвращаются `total`, `period` и `type`. `pending` описывает черновик или требуемое подтверждение; клиент не должен самостоятельно выполнять предложенное действие.

Максимум 2 000 символов текста, 12 000 символов JSON; обязательные UUID, корректный IANA timezone. Модель выдаёт только ограниченный JSON-контракт. Сгенерированные ею SQL и неизвестные операции не исполняются.

## Список

`start=YYYY-MM-DD`, `end=YYYY-MM-DD` (не включается), `type=task|meeting|reminder`, `status=pending|completed`, `limit=1..100`, `offset=0..100000`. Без фильтра статуса возвращаются и завершённые. Без периода возвращается вся история, включая записи без даты. `includeUndated=true` позволяет дополнительно включать записи без даты при фильтре `start` и выводить их первыми.

```json
{ "events": [], "total": 0, "limit": 30, "offset": 0 }
```

Коды: 400 — невалидный ввод, 401 — нет пространства (нужен bootstrap), 403 — чужой Origin у изменяющего запроса, 404 — маршрут/запись/диалог отсутствует, 409 — повторный ID с другим телом или конфликт ревизии диалога, 413 — большое тело, 503 — БД не подключена.

В браузере используется CSRF-защита Origin + SameSite cookie. API предназначен для интерфейса с того же origin; CORS для сторонних сайтов не открыт. Отдельных эндпоинтов прямого изменения событий нет — все изменения проходят бизнес-логику ассистента.
