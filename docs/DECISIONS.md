# Решения и границы прототипа

1. **Один код для локального запуска и облака.** JavaScript ESM и Worker Fetch API; Node HTTP выступает адаптером. Python/FastAPI рассматривался, но доступный хостинг поддерживает Worker: общий модуль позволил избежать второго backend для демо.
2. **SQLite/D1.** Для 1 000 исходных событий не нужны отдельный сервер СУБД и сервис поиска. Repository скрывает платформенный интерфейс, миграции версионируются Drizzle. Локальный адаптер исполняет batch в транзакции; облачный D1 также исполняет batch транзакционно ([официальный API](https://developers.cloudflare.com/d1/worker-api/d1-database/)).
3. **LLM — интерпретатор.** Результат валидируется Zod. Модель не вызывает функции напрямую, не исполняет SQL и не выбирает tenant. Ключ отсутствует в клиенте. Нераспознанные/невалидные действия не записываются. Таймаут — 12 секунд, затем локальный fallback. Квоты, стоимость и качество зависят от выбранного провайдера.
4. **Работа без секретов.** Локальные правила дают воспроизводимое демо и покрывают типовые сценарии задания. Они не эквивалентны универсальной LLM. В интерфейсе показан действующий режим. При отсутствии настроенной модели нельзя утверждать, что диалог выполняется нейросетью.
5. **Поиск.** Snowball, словарь доменных понятий и нечёткие биграммы дают совпадения «контракт → договор», «демонстрация → презентация» и некоторые опечатки. Это ограниченная смысловая близость, не embeddings. Включаемый отдельно LLM-reranker видит до 60 кандидатов: локальные совпадения и при необходимости свежие записи. Он может пропустить старую запись, не попавшую в этот пул. Для полноценной семантики нужен векторный индекс и измерение recall.
6. **Календарные значения.** Дата и время отдельно, без UTC-сдвигов CSV. Часы сервера переводятся в указанный IANA timezone до разбора относительных дат ([Chrono reference](https://github.com/wanasit/chrono#parsing-reference-date--timezone)). Интерфейс и доставка напоминаний фиксированы на Europe/Minsk (UTC+03). Не реализованы пользовательская смена зоны, DST на уровне события и повторения. Периоды: понедельник–воскресенье, `end` исключается. «До конца недели» — воскресенье без придуманного времени.
7. **Уточнения и конфликты.** Задачи допустимы без даты, встречам и напоминаниям нужны дата и время. Недостающие данные хранятся в серверном контексте. Встреча — интервал, по умолчанию 60 минут. Явная длительность поддержана для числового «на N минут/часов». Пересечение не блокирует окончательно: можно подтвердить. Текущую операцию можно отменить.
8. **Сохранение и конкуренция.** Event + exchange + state фиксируются атомарно. Уникальная ревизия предотвращает одновременные изменения одного диалога, `requestId` делает повторы идемпотентными. Разные диалоги могут одновременно изменить одну запись или создать пересечение: в следующей версии нужны version column для событий и сериализация проверки конфликтов.
9. **Изоляция без регистрации.** У каждого браузера случайный идентификатор в HttpOnly cookie и отдельная копия CSV. Это демонстрационное пространство без механизма восстановления аккаунта. Новые браузеры и очистка cookie создают новые пространства. Приватность опубликованного Site дополнительно ограничена доступом владельца. Публичное многопользовательское размещение потребует аккаунтов, rate limit, сроков хранения и quotas.
10. **Речь и доставка.** Использованы браузерные API, чтобы запуск не требовал ещё двух провайдеров. STT зависит от браузера, TTS — от голосов ОС. Напоминания работают в открытой вкладке; фоновые таймеры могут задерживаться браузером. Нужны очередь, push или внешний канал для гарантированной доставки при закрытой вкладке.

## Что специально не реализовано

Реальный внешний календарь, повторяющиеся события, приглашения участникам, авторизация пользователей, нейросетевой векторный индекс и работа микрофона через собственный STT-сервис. Записи CSV не исправлялись лингвистически и не переносились к сегодняшней дате.
